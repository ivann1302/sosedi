# Инструкция по дизайн-системе сайта `sosedi`

Этот файл описывает визуальные и интерфейсные правила для Codex при работе над промо-сайтом `sosedi`.

Использовать как обязательное дополнение к `AGENTS.md` при создании страниц, секций, UI-компонентов, текстовых блоков и визуальных состояний.

# Источник визуальных правил

Основной источник — [brandbook/brandbook.md](brandbook/brandbook.md), визуальный ориентир — [brandbook/brandbook.png](brandbook/brandbook.png). Читать их перед работой над проектом; для UI также просматривать подходящие референсы в `brandbook/`.

Утверждённые логотипы: [основной и дополнительный](brandbook/logos/README.md). Использовать готовые файлы, не набирать логотип обычным текстом и не заменять варианты без указания пользователя.

Этот документ дополняет брендбук требованиями к реализации. Визуальные значения брендбука имеют приоритет. Примеры экранов не являются требованием реализовать отсутствующие функции. Существующий интерфейс может отличаться от новой системы: исправлять затронутый участок в рамках задачи, не проводить попутный редизайн.

---

# Цель дизайн-системы

Сайт должен выглядеть как современный, надежный и понятный промо-сайт сервиса для соседей, локального сообщества и бытовых задач.

Главные качества интерфейса:

* спокойный;
* дружелюбный;
* чистый;
* быстрый;
* доверительный;
* удобный для чтения;
* SEO-ориентированный.

Дизайн не должен выглядеть как сложная SaaS-панель, маркетплейс с перегруженными карточками или декоративный лендинг без полезного содержания.

---

# Основной визуальный принцип

Сначала ясность и контент.

Декор, анимации, сложные сетки, иллюстрации и нестандартные паттерны добавлять только если они помогают:

* быстрее понять продукт;
* усилить доверие;
* показать сценарий использования;
* выделить CTA;
* улучшить восприятие на мобильных устройствах.

Если задачу можно решить хорошей типографикой, сеткой, цветом и семантической разметкой, выбирать это решение.

---

# Тон интерфейса

## Визуальный тон

Предпочитать:

* светлые фоны;
* мягкий контраст;
* понятные CTA;
* чистые секции;
* живые, но не кричащие акценты;
* реальные продуктовые и бытовые сценарии вместо абстрактного декора.

Избегать:

* темных тяжелых тем без причины;
* кислотных цветов;
* крупных декоративных градиентов;
* однотонной палитры из оттенков одного цвета;
* перегруженных карточных сеток;
* визуального шума вокруг CTA;
* декоративных элементов, которые не несут смысла.

## Тон текста

Тексты должны быть простыми, человеческими и конкретными.

Предпочитать формулировки:

* что пользователь получит;
* какую проблему решает продукт;
* почему сервису можно доверять;
* что сделать дальше.

Избегать:

* канцелярита;
* громких обещаний без фактов;
* абстрактных слоганов;
* длинных предложений в UI;
* англицизмов без необходимости.

# Цвета

Использовать палитру и токены из разделов 2–4 и 35 брендбука:

* основной фон: `#F7F4EA`;
* поверхности: `#FFFFFF`, `#FAFAF8`;
* основной текст: `#111111`;
* вторичный текст: `#4D4B47`;
* основной CTA и брендовый акцент: `#FFD400` с текстом `#111111`;
* контрастный CTA на жёлтом фоне: `#111111` с белым текстом;
* границы: `#E7E4DB`;
* коричневый `#B79A78`: редкий акцент, не основной UI-цвет.

Жёлтый применять дозированно. `#85837D` не использовать автоматически для мелкого текста: проверять контраст на выбранном фоне; для читаемого вторичного текста предпочитать `#4D4B47`. Состояния ошибок и другие отсутствующие семантические токены определять при появлении соответствующей задачи.

Правила:

* Не использовать больше 2 основных акцентных цветов в одной секции.
* CTA должен быть визуально очевиден на первом экране.
* Цвет не должен быть единственным способом передать смысл.
* Проверять контраст текста и интерактивных элементов.
* Не создавать отдельные оттенки без причины. Сначала использовать роли выше.

---

# Типографика

Типографика должна быть спокойной, читаемой и мобильной.

Правила:

* Целевая типографика: Nunito Black для крупных заголовков, Nunito ExtraBold для `h3`, Montserrat для основного текста, Caveat только для эмоциональных акцентов — по разделу 5 брендбука и уточнению пользователя от 23 сентября 2026 года.
* До подключения проверить точные файлы, кириллицу, начертания и возможность использования шрифтов. Загружать только необходимые начертания; существующий шрифт не считать эквивалентом брендового. Если файлов нет, явно отмечать отклонение.
* Не масштабировать шрифт через ширину viewport.
* Для крупных заголовков использовать отрицательный `letter-spacing` в пределах значений раздела 6 брендбука; проверять русские переносы.
* Размеры и межстрочные интервалы брать из разделов 6–7 брендбука; на ширине 320px адаптировать при необходимости для предотвращения переполнения.
* Длина строки в текстовых блоках: примерно 60-75 символов на десктопе.
* Заголовки должны помогать структуре страницы, а не быть декором.

Рекомендуемая иерархия:

* `h1`: только один на странице, понятное название продукта, страницы или предложения.
* `h2`: основные секции.
* `h3`: группы внутри секций, карточки, FAQ.
* Обычный текст: комфортный размер и line-height, без плотного набора.

Для промо-страниц:

* hero-заголовок должен быть коротким;
* supporting copy должен объяснять пользу;
* CTA-текст должен быть глагольным и конкретным.

---

# Сетка и отступы

Использовать mobile-first.

Базовые правила:

* Контент страницы ограничивать контейнером.
* Секции делать полноширинными, с внутренним контейнером.
* Не превращать каждую секцию в карточку.
* Не вкладывать карточки в карточки.
* Вертикальные отступы должны создавать ясный ритм между секциями.
* На мобильных устройствах сетки должны становиться одноколоночными.

Рекомендуемые размеры:

* Контейнер: ориентир `1360px`, допустимо `1280–1440px`.
* Горизонтальные поля: 48–72px на десктопе, ориентир 20px на мобильных (16–24px).
* Вертикальные поля секций: 110–160px на десктопе, 72–96px на мобильных; адаптировать к содержанию.
* Радиусы: карточки 20–24px, крупные поверхности 28–32px, поля 16px, основные кнопки pill — по разделам 11 и 18 брендбука.
* Границы: тонкие и спокойные.

# Компоненты

## Кнопки и ссылки

Кнопки использовать только для действий.

Ссылки использовать для навигации.

Основные варианты:

* Primary: главный CTA.
* Secondary: вторичное действие.
* Text link: навигация или менее важное действие.

Правила:

* Текст кнопки должен быть коротким и конкретным.
* На странице не должно быть много конкурирующих primary CTA.
* Интерактивные элементы должны иметь hover, focus-visible и disabled-состояния, если состояние применимо.
* CTA: высота 54–60px на десктопе, минимум 48–52px на мобильных согласно брендбуку; текст должен помещаться при увеличении масштаба.

## Карточки

Карточки использовать для повторяемых сущностей:

* преимущества;
* шаги;
* отзывы;
* статьи блога;
* вопросы FAQ;
* сценарии использования.

Правила:

* Карточка должна иметь одну смысловую задачу.
* Не перегружать карточки большим количеством текста.
* Не использовать карточку как универсальную обертку для каждой секции.

## Формы

Если появятся формы:

* поля должны иметь связанные `label`;
* ошибки должны быть понятны без цвета;
* обязательные поля должны быть очевидны;
* форма должна работать с клавиатуры;
* не добавлять клиентский JavaScript без необходимости.

# Секции промо-сайта

## Главная

Первый экран должен сразу объяснять:

* что такое `sosedi`;
* для кого сервис;
* какую задачу решает;
* какое главное действие доступно пользователю.

Hero не должен быть пустым декоративным блоком.

## Описание продукта

Показывать реальные сценарии:

* найти нужную вещь рядом;
* взять вещь в аренду;
* сдать свою вещь;
* пользоваться вещами совместно;
* скачать приложение.

## FAQ

FAQ должен быть коротким, индексируемым и полезным: одна колонка, обычно 4–6 вопросов, без kicker и лишнего вводного блока согласно разделу 28 брендбука.

Использовать обычную семантическую разметку. Клиентский аккордеон добавлять только если он реально улучшает страницу.

## CTA-блоки

CTA должен быть связан с контекстом секции.

Не повторять один и тот же большой CTA после каждого блока без пользы.

## Блок скачивания приложения

Показывать:

* краткую пользу;
* доступные платформы;
* понятный статус, если приложение еще не опубликовано;
* альтернативное действие, например подписка на запуск.

Не ставить неработающие ссылки на магазины приложений.

## Блог

Для блога важны:

* читаемость;
* семантическая структура;
* SEO-заголовки;
* понятные категории;
* аккуратные превью статей.

## Страница для бизнеса

Тон должен быть чуть более деловым, но не холодным.

Показывать:

* пользу для локального бизнеса;
* примеры размещения;
* доверие;
* простой CTA.

## Юридические страницы

Дизайн максимально спокойный.

Приоритет:

* читаемость;
* структура;
* даты обновления;
* понятные заголовки;
* отсутствие декоративного шума.

# Изображения и медиа

Использовать изображения только когда они помогают понять продукт или ситуацию.

Предпочитать:

* реальные бытовые и городские сценарии;
* скриншоты продукта, когда они появятся;
* простые иллюстрации, если нет реальных материалов;
* оптимизированные изображения через возможности Next.js.

Избегать:

* темных размытых фото;
* стоковых изображений без связи с продуктом;
* декоративных абстракций;
* тяжелых видео на первом экране;
* изображений, которые мешают читать текст.

---

# Адаптивность

Дизайн строить mobile-first.

Проверять:

* ширину 320px;
* типовой мобильный экран;
* планшет;
* десктоп;
* широкий десктоп.

Правила:

* Текст не должен выходить за пределы контейнера.
* Кнопки не должны ломаться на длинных русских формулировках.
* Высоту Hero определять содержанием и композицией брендбука; не обрезать заголовок или CTA ради показа следующей секции.
* Сетки преимуществ и карточек должны сохранять понятный порядок чтения.
* Интерактивные элементы должны быть удобны для касания.

---

# Accessibility

Минимальные требования:

* семантические теги `header`, `main`, `section`, `nav`, `footer`;
* один `h1` на страницу;
* логичная иерархия заголовков;
* понятные `alt` для содержательных изображений;
* пустой `alt` для декоративных изображений;
* видимый `focus-visible`;
* достаточный контраст;
* ссылки и кнопки должны быть понятны вне контекста, где это возможно.

Не скрывать важный текст только в изображениях.

---

# Анимации

Анимации должны быть минимальными.

Допустимо:

* мягкий hover;
* короткий transition цвета, тени или transform;
* аккуратное раскрытие интерактивного элемента, если оно не мешает.

Избегать:

* сложных scroll-анимаций;
* постоянного движения;
* анимаций, задерживающих чтение;
* анимаций, требующих отдельной библиотеки.

Учитывать `prefers-reduced-motion`.

---

# Реализация

Следовать `AGENTS.md`.

Приоритет реализации:

1. Server Components.
2. Семантический HTML.
3. CSS/SCSS или Tailwind по уже выбранному паттерну проекта.
4. Минимальный клиентский JavaScript только для реальной интерактивности.

Не добавлять:

* UI-библиотеки;
* библиотеки анимаций;
* икон-паки;
* слайдеры;
* сложные дизайн-токен системы;

без явной необходимости.

Если используются токены, держать их простыми:

* цвета;
* типографика;
* spacing;
* radius;
* shadow.

Не создавать сложную инфраструктуру дизайн-системы до появления повторяющихся компонентов.

* не ухудшена ли семантика;
* не нарушена ли адаптивность;
* понятен ли CTA;
* сохранена ли читаемость русского текста;
* запущены ли доступные проверки из `AGENTS.md`, если изменялся код.
